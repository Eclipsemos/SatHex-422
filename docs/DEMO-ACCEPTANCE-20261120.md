## 执行内容

1. 板上本地gcc编译aarch64静态样例，不联网下载镜像。样例软件运行后输出READY:v1或READY:v2并等待正常退出；算法模式实际计算1到100之和，输出SUM=5050和递增tick，约30秒自然完成。
2. 生成三个独立Docker镜像v1、v2、bad。镜像归档作为真实上注文件：v1/v2各573952字节、1151包，bad为563712字节、1130包。通过板上两路PTY分别送控制帧与3A上传帧，经SQLite持久化、CRC校验后docker load，再创建非特权、只读、无网络、64MiB限制的样例容器。
3. 软件后端只接受本地可信清单中SHA256和不可变image ID匹配的本次样例包；未授权归档不交给Docker。它不等同面向任意外部包的完整安全安装器。
4. TYPE30完成17/53/54/04/56的样例通路；TYPE21完成算法83/85/81和软件80/87，61B遥测更新APP1运行和完成状态。被暂停算法在87恢复时unpause，这是本样例的明确绑定。
5. 软件从v1升级v2成功；bad镜像启动退出17，健康检查失败，旧v2容器恢复运行，56仍返回v2，r014=40。验证活动槽拒绝覆盖、拒绝擦除；仅测试保护拒绝，没有宣称成功删除软件槽内容。
6. 物理COM3/9600/8N1运行现有正式AT服务，临时只把本次样例容器加入白名单，实际START/INFO/STATS/RESTART/STOP均通过；测试后完整恢复配置，白名单重新为空。原gallant_ramanujan容器启控请求返回NOT_ALLOWED且保持停止。

所有镜像、样例容器和临时目录已清理。原有hello-world镜像与gallant_ramanujan容器保留。gs422、Docker和SSH均active/enabled、NRestarts=0，主板保持运行。源码保留于/home/hzx/demo-live-20261120供复现。
