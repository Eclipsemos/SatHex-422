# HT226 短指令与 X26 样例接口

对应遥控大表「HT226指令表」第 19–27、34–35 行。控制口接收有效载荷 `21 W0 W1 W2 W3 W4 W5 W6`，W0 为下表指令码。沿用普通 EB90 链路的大端长度、有效载荷 SUM16 和 09D7 帧尾。例如选择备数传的整帧为 `EB 90 00 08 21 40 01 00 00 00 00 00 00 62 09 D7`。原 K/D 有版本和序号，继续按原来的长度与参数解释。

| 码 | 六字节参数 | 执行结果 |
|---|---|---|
| 40H | W1 为 00 主数传、01 备数传，其余零 | 记录 HT226 下传链路。主、备独立于原 D0352 的数传、测控选项。 |
| 41H | W1 为 11–14H 或 20–22H，W2 为 1–255，其余零 | 选取该类型最新 N 个已发布文件，按修改时间从新到旧，同时间按文件名字典序降序。数量不足、为零、类型未注册时失败并清空待播清单。 |
| 42H | 全零 | 依次从已选清单直接发送源文件，保留文件边界。确认清单及通道后进入回放中，完成置 2。源文件被替换或输出失败置 3。 |
| 43H | 全零 | 取消当前回放，等待发送端退出，完成结果可查询；停止后的帧计数保持，再启动从清单开头发送。 |
| 13H | W1 为 01–06H，其余零 | 依次对应平台日志、平台 HK、守护进程日志、系统日志、OTA 备份和上注临时文件。仅清理指定类别中已发布的普通文件。 |
| 51H、52H | 全零 | 停止固存接收并等待工作线程退出；查询返回调度状态、帧数、字节数及 CRC 错误计数。 |

短指令无即时应答及发送端序号。接收端为每次请求分配本地收据号。现有 TYPE15 结果查询返回 TYPE16，包含指令码、状态、退出值，以及 JSON 中的 `receipt`、`device`、`words`。13H 的设备码为 01H，其余六条为 02H。52H 的结果另含 `link`、`play_state`、`play_frames`。44 项遥测布局沿用原表。

## 现场与样例数据

本地生产端将完整文件原子改名发布到 `ht226_root/replay/<两位大写类型码>/`。待清理文件按六类发布到 `ht226_root/clean/<两位大写类型码>/`。两个目录树独立。接收的指令只携带数值类型。扫描跳过点文件、子目录和符号链接；清理重试只作用于该目录中仍存在的普通文件。现场可将 NFS 接入发布目录，并为主、备输出分别绑定文件发送驱动。驱动签名为 `send(name, source, cancel, progress)`，每发送一帧调用一次 progress，及时检查 cancel。

板上实验配置沿用显式启用的 fixture_io_root，默认在其 ht226 子目录内建立各类别的空目录，并将输出分别写入 main-downlink、backup-downlink。文件输出样例按 4096 B 分块计数；物理下传驱动使用实际帧边界。真实星务的遥测封装及主备下传设备仍需对接。单元和执行链测试见 tests/test_ht226_short.py。

## 2026-11-23 板上验收

lab6 通过 180 项单元测试。安装后 PC 通过 COM3 实发 7 条短指令，共核对 16 条成功或拒绝的执行结果。主、备样例各收两个 5000 B 文件，逐字节比对一致，分类清理删除一个样例并保留另一类别文件。板上受控发送端另验证传输中停止、重新启动和固存停止后的计数。
