# D0351旧上注路径明确配置

用户要求普通TYPE21/25保留感算K/D表，同时TYPE30/32使用OTA新文档。本模块只补全旧D0351文件接收，不将04H变参格式当作新版6字节激活请求。新版快速上注仍走UART8/3A。

旧表没有明确参数1、ByteMap长度及两个校验的覆盖范围。按用户授权自主设计，定义项目配置`legacy-file-v1`：data_length为当前包文件数据字节数N，bitmap_size为ceil(total_frames/8)，packet_checksum为当前N字节逐字节累加mod65536，file_checksum为整文件CRC-16/CCITT-FALSE。它是新增设计约定，不声称兼容某个未提供的旧发送端；发送端必须使用同一配置。

其他字段保持原表：文件大小u32、总帧数u32、8位包序号、512B/包（最后一包按文件长度截取）、4B保留0，故最大256包/128KiB。逻辑参数超过总线504B有效数据上限时沿用已设计的TYPE29分片，重组后按TYPE25/04解析。该限制不能用新版32位包序号自动替换。

接收由显式配置的LegacyUpload执行，数据和元数据采用SQLite同步事务持久化。乱序、相同包重复、缺口定位和重启续传均有测试；冲突重复、不同文件元数据、错误长度/位图/累加和均拒绝；收到全包后进行整文件CRC，失败不可导出。相同坏文件最后包重发不能把CRC失败改判为成功。文件ID耗尽时拒绝，不回绕为0。

K1103/02允许旧路径接收；K1102/00取消会话并清空该接收器自己的暂存包，保留错误计数和文件ID序列。要开始另一旧文件须明确关闭/重开门控。新版53开始和旧D0351活动接收互斥，防止r008–014混合两个上传会话；遥测按当前活动的接收配置取快照。

本路径成功表示完整软件文件已接收且校验通过，不代表已部署/激活；不能按原表含糊的“写入指定分区”解释为裸设备烧写，因为D0351没有目标区域参数。部署须使用显式绑定的软件后端及新OTA激活流程，旧文件到新激活包库的转换尚未实现。

2026-11-20主板测试：完整131项单元测试通过；live_file_commands中通过双PTY发送3包1280B（顺序2、0、1），导出逐字节一致、TMG010=3、TMG014=23。实际物理控制链路的分片压力和UART8上注仍未验收。
