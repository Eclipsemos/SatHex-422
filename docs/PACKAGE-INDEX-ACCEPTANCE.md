# 软件历史包与初始包索引验收

2026-11-20，X26主板真实Docker样例，双PTY控制/上注。新增PackageIndex及DurableDemo集成，覆盖04H的00、01–80、F0–FF选择规则；不把未注册索引视为成功。

## 实现规则

- 00仍选择当前完整上传且CRC通过的包。
- 健康检查成功的软件版本获得01–80范围内第一个未占用历史索引，同一个归档SHA256重复注册返回原索引。索引持久化为JSON并fsync/原子替换，管理器重启不会按目录排序重排。
- F0–FF只能通过本机register_initial明确预置已验证归档；相同索引不可改绑另一个digest。不存在索引返回FF拒绝，不回退到“最近包”。
- 注册表只映射到本地可信catalog中的SHA256；每次解析都重新检查归档存在、不是符号链接且hash正确。串口数字不转换为任意文件路径。
- 历史/初始包加载选择当前非活动软件槽，继承已有镜像ID校验、真实容器健康检查、失败回退和持久事务。不会覆写Ubuntu或分区。
- 已激活且正在正常运行同一包时，重复索引选择返回成功且保留原容器ID；暂停/未运行不走此快捷成功路径。
- 128个历史索引用完后不驱逐或重分配旧引用，新成功版本仍可为当前版本但不分配额外历史索引。包库自动淘汰/配额暂未实现，须另行完成。

## 主板实测

完整158项单元测试通过，7.785秒。新增5项覆盖稳定索引/重复、初始包显式注册与不可覆盖、损坏/丢失/链接归档拒绝、注册表满时不改绑、历史归档适配器不覆盖目标文件。

完整`live_demo_deployment.py --durable --unified`退出0，在之前软件清理/重上传恢复后增加：

1. 读取v1的历史索引，显式将同一可信包注册为F0。
2. 关闭并重开软件管理实例，断言注册表完全一致。
3. 通过TYPE30/04历史索引恢复v1，56H版本返回v1。
4. 重复发送同一历史索引，容器ID不变。
5. FF未注册，04H返回FF且版本仍v1。
6. 通过v2历史索引恢复v2，再用F0恢复v1，最终通过v2历史索引回到v2。
7. 统一文件/算法/OTA样例再次通过，所有测试容器和镜像清理完成。
