# 广播时间、擦除遥测与三条遥控的设计

TMG004 存最近一次收到的广播 UTC。时间字段沿用无符号四字节 Unix 秒和大端编码。总线文档规定广播类型 CC，本分支建议时间子码 01，即有效数据为 `CC 01 UTC[4]`。卫星转发和地面发送使用相同格式，接入时需确认上游子码。接收成功不应答，重复、跳时及回拨均按到达顺序取最后值。首个有效广播前返回 0；服务重新启动清空缓存。遥测查询、传感器刷新和本地 RTC 均不能推进该值。

TMG014 保持新版大表 P15 的单字节枚举。K1118 和 OTA Z55 共用擦除处理。在进入有后端的擦除调用前发布 10H；后台调用完成并返回成功后发布 11H，失败为 40H。TYPE11 遥测和 TYPE32 进度查询均可见。状态保持到后续有效的传输/校验/加载阶段，无人为延时；很快的擦除可能在两次轮询之间完成。校验通过的包仍保持原接收器状态，以便后续激活。10H 表示已进入软件逻辑区域的擦除处理，包括后端检查；仅 11H 可视为完成。

以下三项是待评审的执行设计。线上的码和现有参数顺序均沿用感算 K/D 表。

| 指令 | 入参及处理 | 成功判据、异常和复测 |
|---|---|---|
| K1104 / 83H | W1 为已注册算法 ID；W2 为 0–255 的优先级，建议数值越大越先启动，同级 FIFO；W3=1 独占、2 允许并发；W4=1 使用后摩、2 使用 CPU；W5–W6 填零。每个 ID 绑定本机审核过的镜像摘要、入口、CPU/内存预算、加速能力及互斥资源。建议并发上限 2、等待队列 8，按非抢占调度运行。独占任务与任何运行任务互斥，同 ID 不重复启动；缺后摩时报能力不可用，不改跑 CPU。 | 合法请求建立任务记录；容器启动且读到就绪信号才进入运行态。TMG015 记最近成功配置的 ID，TMG016 记最近进入运行的 ID，多任务状态看各 APP 两位，TMG017 记最近完成的 ID。失败/超时保留退出原因；停止/暂停按 ID，已有 SEQ 重发不排第二份。验收要同时提交两个不同 ID、改变优先级、压满队列、强制异常退出，以及分别测有卡／缺卡。目前仅 CPU 单任务 ID1 样例已运行。 |
| K1115 / 32H | W1=1 开、2 关；W2=0 内存盘、1 SSD；W3=1 连续定姿、2 广域、3 重点目标；W4–W6 为零。建议每次开始固定介质和模式，同参重复返回原文件号，变参重入返回 BUSY。内存盘核实 tmpfs；SSD 以配置的文件系统 UUID、挂载点及实际设备核验，按保留水位检查可用空间。驱动确认星敏模式后新建 partial，并按帧保存序号、长度、时间及负载。 | 收到完整帧才累计；SSD 写满、拔出、源断开等使任务失败并保留 partial。关闭需停止接收、排空有界缓冲、同步文件和目录并提交索引，关闭后帧数不再增加。重启后标记未提交记录为中断。验收矩阵为两种介质×三种模式的开／关，以及重复开启、满盘、掉线。现有样例只验证内存盘，SSD 后端及真星敏待接入。 |
| D0351 / TYPE25 04H | 沿用 legacy-file-v1：每包数据长度 N、保留零、文件大小、总帧数、位图字节数、8 位包号、最多 512B 数据、包累加和与全文件 CCITT-FALSE。按现有 TYPE29 分片承载超长逻辑包。允许乱序、同内容重传、断点恢复；冲突包拒绝。最多 256 包、128KiB。 | 建议 CRC 成功后从持久暂存导出到临时文件，按 SHA256 查本地受信包目录，核对组件、版本及展开上限，再原子登记为待激活包。验收文件和回传进度对应 TMG008–014；登记成功不改运行版本。由显式 TYPE30/04 索引命令激活非活动软件槽，健康检查失败恢复旧业务。未注册或过大拒绝；超出 128KiB 的包使用 UART8 新协议。必须用能放入旧流的小型真实软件包，经历接收→登记→激活→56H查询→坏包回退。已有 900/1280B 文件接收证据；旧文件登记到激活包库的桥接待实现。 |

K1104 的优先级方向、并发数和队列深度，K1115 的文件策略，以及 D0351 的受信目录桥接都是项目设计取值，可在实现前调整。星务正式广播联试、后摩、星敏及 SSD 验收按实际接入情况记录。

验证记录：X26 上 166 项单元测试通过。lab4 安装后从 COM3 发两次广播，三次回读分别为 1795402617、1795402617、1795402639；在非活动槽执行 55H scope1 后，TYPE12 和 TYPE33/53 均返回 11H。10H 由阻塞后端在两种指令路由的执行窗口内验证；21H、FFH 未计入本轮通过。
