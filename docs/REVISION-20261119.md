# 20261119 新版遥控遥测与重构协议设计

本文件是本次新资料的设计入口，覆盖19项感算K指令、4项感算D指令、44项感算遥测。旧版SATELLITE-FRAMES和PAYLOAD-SERVICES-DESIGN中的OTA与遥测布局不作为新版依据。原件未修改，精确源文件SHA256、单元格、字段长度与参数保存在spec-20261119.json。

接口补充：用户提供的软硬件接口DOCX明确遥测遥控UART6、快速上注UART8_RX；结合X26软件说明配置为ttyS6/ttyS8。已新增双UART接入层和Linux PTY测试，详见[X26接口映射](X26-INTERFACE-MAPPING.md)。当前固件ttyS8实际工作状态仍需上板确认。

用户已于本次会话确认：TYPE21/25按感算K/D表，TYPE30/32按OTA文档，r013/r014采用OTA文档枚举；CRC统一CRC-16/CCITT-FALSE（poly=1021、init=FFFF、refin=false、refout=false、xorout=0000，123456789→29B1）。同码不同格式按TYPE显式区分，不靠长度猜测。算法执行仍留空。

传感器新确认：lab11 起 TMG006 专指外接后摩卡，TMG007 为 RK3588 内置 NPU 温度；8位温度FF、16位电压/功耗FFFF为无效。见MEASURED-TELEMETRY-ACCEPTANCE.md，已完成真实COM3完整帧读回和无效值解码，后摩卡尚未安装。

2026-11-20用户明确升级对象通常为软件。当前采用[载荷软件目录主备方案](X26-OTA-STORAGE-DESIGN.md)：APP1/eMMC1对应软件A目录，APP2/eMMC2对应软件B目录，boot1/boot2保留不执行。此前双Ubuntu与重新分区提案撤回，未曾在主板实施。

验收目标分为：源表逐项覆盖、软件行为测试、发送端互通、真实载荷动作及实机时序。不能以参数校验测试或临时目录文件写入代替Flash烧写验收。当前主板已按用户要求关机；本次只在本机Windows和WSL Linux运行测试，未刷写主板、未改变主分支。

## 两通道帧布局

共同外层：EB90(2B)、L(2B大端)、payload(L)、SUM16(2B大端)、09D7(2B)。SUM为payload每字节累加模65536。L≤504；数据字段包含标记字节不截断帧。

OTA请求payload按DOCX为 `TYPE(30或32) CODE W1..W6`，不加上一版实验头的VERSION/SEQ；控制应答为`31 CODE RESULT`，版本应答为`33 56 ASCII\0`。普通TYPE21/25保留原实验头，其是否与星务包直接对接仍待总体确认。不能在同一类型内自动猜测头部。

快速上注payload固定504B：`3A SEQUENCE:u32 DATA[499]`，整帧恰好512B。首包DATA前6B为`FILE_SIZE:u32 FILE_CRC:u16`，首包最多493B文件内容，后续499B；尾包剩余补0且校验补0。总包数=ceil((file_size+6)/499)。控制和数据各自Decoder，数据通道绝不发送应答，不把原控制SEQ防重逻辑套用到32位数据序号。

控制采用115200/8N1作为新版OTA明确规定的配置；旧总线文档中的奇偶位要求仍需总体协调。参考库没有自动修改已部署UART参数。

## 61字节遥测区

44项布局详见[逐字段表](TMG-LAYOUT-20261119.md)。该61B仅为表中业务数据区，不含APID、外层类型或实验头。revised_runtime当前沿用5B实验应用头，TYPE11请求对应TYPE12+VERSION+SEQ+CODE+61B（整帧74B）。正式外层遥测头仍需与星务对接。旧space_service维持原60B实验健康遥测；两个入口不能混用。

所有多字节字段大端；TMG038低32位先于TMG039高32位是表格明确规定的词序。算法状态APP15在33字节bit7..6，APP0在36字节bit1..0。算法ID和状态在未配置情况下保持0（未运行），不虚构任务完成。

TMG004从最近有效的广播UTC秒值开始，查询时累加接收后经过的整秒数；本机系统时钟不参与此字段。TMG005是RK3588整机功耗，不得使用后摩板卡功耗代填；需要实测电压与电流或专用功率传感器。TMG006/007量化为整摄氏度，TMG034为0.01V，超出unsigned范围拒绝。原表缺测值现已由用户补充：温度FF、电压/功耗FFFF。缺失传感器可发布明确无效标记，不能宣称全有效。

TMG001/002分别统计正确接收和指令错误，执行失败不冒充接收格式错误；TMG003统计两通道错误帧。TMG040按单调时钟每秒增1、8位回绕，不依赖收到查询。其余计数暂按位宽回绕设计但需总体认可。TMG042–044固定0，不擅用作有效位。61B打包必须提供全部字段，不静默补缺值。

## OTA暂存与恢复

ota_staging使用SQLite FULL同步事务提交包数据与状态，提交成功后才增加r010；返回值仅供进程内调用，不是数据通道应答。测试包括序号缺口、相同包去重、不同内容重复拒绝、尾包补0检查、重启恢复、CRC阶段中断重试、容量限制和导出字节一致性。

元数据首包丢失时暂不接收后续包，r009=0；主机必须重发首包，再按缺口补传。收到乱序后续包后可以保留，r009定位最小缺口；收齐后r009暂约定FFFFFFFF，无首包为0，该哨兵需总体确认。r012采用表中“已收不同包数/总包数”取整，与DOCX按字节描述有细微差异，明确列为所选解释。

开始请求完全相同且正在接收时视为重试；不同参数返回忙。新的明确开始请求在上一会话终止后创建新本地file_id，该ID来源是新增约定，因为控制参数没有文件标识。缺少线上会话ID意味着旧会话延迟包无法可靠区分，正式上线应增加清空/会话握手或隔离窗口。暂存库只允许单个拥有者进程，不支持两个接收服务并发写同一会话。

参考服务采用显式`interpretation=ota-doc-v1`，新版runtime固定验证CRC profile为已确认的CCITT-FALSE。Z55与Z04的真实Flash后端尚未具备，返回FF，不擦文件也不伪造版本更新。成功接收/导出不等于固件已加载。4GiB边界仅验证序号/长度算术，未开展4GiB吞吐、磨损或断电压力测试。
