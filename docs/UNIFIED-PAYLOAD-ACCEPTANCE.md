# 统一载荷执行器样例验收

2026-11-20，X26主板Ubuntu22.04/aarch64，Docker29.1.3。目标是将此前分散的文件、软件、算法和两种上注执行器组合到同一个Revised运行实例；不能把临时样例验收称为正式现场部署。

## 实现与配置

PayloadBackend显式分发文件动作和软件动作，支持另行绑定BoardReboot。没有绑定的驱动仍报错。记录/回放/固存正在运行时，组合层拒绝软件升级和整板重启；算法正在运行时拒绝整板重启。已有Docker内部检查也拒绝活动算法期间的软件切换。没有把未知命令直接代理到shell或Docker API。

live_demo_deployment增加`--durable --unified`：

- 软件后端为持久DurableDemo，使用本次构建的可信v1/v2/bad样例镜像；算法ID1实际求和5050。
- 文件后端为FileServices，数据目录位于/dev/shm真实tmpfs；星敏/固存源是明确测试替身，回放输出为两个真实文件。
- TYPE21/25指令、TYPE30/32新OTA、TYPE3A上传以及旧D0351 LegacyUpload共存；软件后端恢复后重新绑定到同一个组合层。
- 两路串口为主板PTY，所有待测命令通过外层帧编解码和异步结果查询，未直接绕过协议调用业务以冒充验收。
- 新增4项组合单测：动作归属、活动记录阻止升级/重启、运行算法阻止重启、重启必须明确绑定。

## 结果

完整144项主板单元测试通过（8.294秒，无跳过）。真实组合流程退出0。22项非重启指令在同一配置有成功业务路径，K1109不重复执行，当前组合实例明确未绑定重启动作；该指令另有此前COM3重启与boot_id变化证据，见K1109-REBOOT-ACCEPTANCE.md。

同时复验了v1安装、管理器恢复、子进程中断回退、v2升级、坏版本失败回退、候选文件清理、活动槽保护和未知算法拒绝。物理传感器值在此测试中明确为模拟fixture，不能用此日志证明电压功耗或NPU测量准确。

结束后仅保留原hello-world镜像和gallant_ramanujan停止容器，gs422/Docker/SSH均active。样例文件、容器、镜像与tmpfs目录清理完成；未修改正式AT服务配置或启动项。

## 全目标仍未满足的部分

1. 还没有可供用户长期使用的统一现场守护进程及实际外设配置；本轮是显式测试脚本内组合配置。
2. 物理ttyS8上传缺第二只转换器，用户已确认。真实星敏、固存和下传链路仍非实机输入/输出。
3. 正式UTC校时、实际电压/功耗单位与NPU温度对象、缺测编码需落实，不能用模拟44字段覆盖代替测量验收。
4. K1118仅scope1候选文件实际删除及活动槽保护通过；scope0安装版本清理、历史/初始包选择、大文件/分段、控制时限与2ms时序尚未全部完成。
5. D0351接收成功尚未自动关联到已验证软件包历史索引；不能把文件接收当成该文件已经运行。
